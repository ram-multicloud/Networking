# Networking Fundamentals — Subnet Mask, IP Addressing & VLSM


## Purpose of Subnet Mask

A **subnet mask** is a 32-bit number that tells a device which portion of an IP address is the **Network ID** and which is the **Host ID**. It acts as a filter or boundary marker.

> **In simple terms:** The subnet mask is a filter that separates the network part from the host part of an IP address.

### Example

```
IP Address  : 192.168.10.0
Subnet Mask : 255.255.255.0

  255.255  →  Network ID portion  (192.168 is the network)
  255.0    →  Host ID portion     (10.0 are the hosts)
```

### Rules for IP Addresses

- An IP address has **4 numbers** separated by dots — each called an **octet** (8 bits)
- Each octet can only hold values from **0 to 255**
  - `00000000` = **0**
  - `11111111` = **255**
- Special reserved values:
  - All **0s** → **Network ID** (e.g., `192.168.1.0`)
  - All **255s** → **Broadcast Address** (e.g., `192.168.1.255`)

## IP Address Classes (Classful Addressing)

IP addresses are grouped into classes based on their size. Each class defines how many networks and hosts are possible.

| Class | First Octet Range | Networks | Hosts per Network | Default Subnet Mask |
|-------|-------------------|----------|-------------------|---------------------|
| **A** | 1 – 126 | 126 | 16,777,214 | `255.0.0.0` |
| **B** | 128 – 191 | 16,384 | 65,534 | `255.255.0.0` |
| **C** | 192 – 223 | 2,097,152 | 254 | `255.255.255.0` |
| **D** | 224 – 239 | Multicast | — | — |
| **E** | 240 – 255 | Reserved | — | — |
| **Total** | | | **~3.72 Billion hosts** | |

```
Diagram — Classful IP Ranges

  Class A:  1.0.0.0       –  126.255.255.255   (Large orgs)
  Class B:  128.0.0.0     –  191.255.255.255   (Medium orgs)
  Class C:  192.0.0.0     –  223.255.255.255   (Small orgs)
  Class D:  224.0.0.0     –  239.255.255.255   (Multicast)
  Class E:  240.0.0.0     –  255.255.255.255   (Reserved)

  Total usable hosts: ~3,720,314,628
```

## Private vs Public IP Addressing

Private IP ranges are **reserved** for internal use and are not routable on the public internet. Devices in private ranges use **NAT** to access the internet.

| Range | Class | Usage |
|-------|-------|-------|
| `10.0.0.0 – 10.255.255.255` | A | Large private networks (e.g., AWS VPCs) |
| `172.16.0.0 – 172.16.255.255` | B | Medium private networks |
| `192.168.0.0 – 192.168.255.255` | C | Home & small office networks |
| `169.254.0.0 – 169.254.255.255` | — | Link-local / APIPA (no DHCP available) |

```
Diagram — Private vs Public IP Space

  ┌─────────────────────────────────────────────────────┐
  │  Public Internet  (routable, globally unique IPs)   │
  │   ┌──────────────────────────────────────────────┐  │
  │   │  Private Network (10.x / 172.16.x / 192.168.x)  │
  │   │   [Device A]  [Device B]  [Device C]         │  │
  │   │              ↓ NAT Router ↓                  │  │
  │   └──────────────────────────────────────────────┘  │
  └─────────────────────────────────────────────────────┘
```

## CIDR — Classless Interdomain Routing

CIDR replaces the rigid class system with a flexible **prefix length** notation. Instead of fixed class masks, you specify exactly how many bits are used for the network.

### Notation Comparison

```
Without CIDR (classful):           With CIDR:
  IP:   192.168.10.0                192.168.10.0/29
  Mask: 255.255.255.248

  /29 means 29 bits = network,
  3 bits = hosts → 2³ - 2 = 6 usable hosts
```

### How the Prefix Works

```
Diagram — CIDR Bit Breakdown for /24

  IP:   11000000.10101000.00001010.00000000  (192.168.10.0)
  Mask: 11111111.11111111.11111111.00000000  (/24)
        |────────── 24 network bits ─────────|── 8 host bits ──|

  Usable hosts = 2^8 - 2 = 254
```

### CIDR Ranges Overview

```
Diagram — CIDR Subnet Sizes

  /8   →  255.0.0.0       →  16,777,216 IPs  (Class A equivalent)
  /16  →  255.255.0.0     →      65,536 IPs  (Class B equivalent)
  /24  →  255.255.255.0   →         256 IPs  (Class C equivalent)
  /32  →  255.255.255.255 →           1 IP   (Single host)
```

## 7. Variable Length Subnet Mask (VLSM)

**VLSM** allows you to divide a network into subnets of **different sizes** based on actual need — instead of wasting IPs by giving every subnet the same fixed size.

> **Problem with fixed subnets:** If you split a `/24` into 4 equal `/26` subnets (62 hosts each), a department needing only 10 hosts wastes 52 IPs.
>
> **VLSM solves this** by letting each subnet be exactly as large as it needs to be.

### How VLSM Works

Start with a base network and carve out subnets from **largest to smallest** requirement.

### Example: Split `192.168.10.0/24` for 4 Departments

| Department | Hosts Needed | Assigned Subnet | Subnet Mask | Usable Hosts |
|------------|-------------|-----------------|-------------|--------------|
| Sales | 100 | `192.168.10.0/25` | `255.255.255.128` | 126 |
| HR | 50 | `192.168.10.128/26` | `255.255.255.192` | 62 |
| IT | 20 | `192.168.10.192/27` | `255.255.255.224` | 30 |
| Admin | 10 | `192.168.10.224/28` | `255.255.255.240` | 14 |

```
Diagram — VLSM Address Space Allocation

  192.168.10.0/24  (256 IPs total)
  ├── 192.168.10.0/25    → Sales  (126 usable)  [.0   – .127]
  ├── 192.168.10.128/26  → HR     (62 usable)   [.128 – .191]
  ├── 192.168.10.192/27  → IT     (30 usable)   [.192 – .223]
  └── 192.168.10.224/28  → Admin  (14 usable)   [.224 – .239]
      192.168.10.240/28  → [Available for future use]
```

### VLSM Subnet Cheat Sheet

| CIDR | Subnet Mask | Total IPs | Usable Hosts | Formula |
|------|-------------|-----------|--------------|---------|
| `/24` | `255.255.255.0` | 256 | 254 | 2^8 − 2 |
| `/25` | `255.255.255.128` | 128 | 126 | 2^7 − 2 |
| `/26` | `255.255.255.192` | 64 | 62 | 2^6 − 2 |
| `/27` | `255.255.255.224` | 32 | 30 | 2^5 − 2 |
| `/28` | `255.255.255.240` | 16 | 14 | 2^4 − 2 |
| `/29` | `255.255.255.248` | 8 | 6 | 2^3 − 2 |
| `/30` | `255.255.255.252` | 4 | 2 | 2^2 − 2 |
| `/32` | `255.255.255.255` | 1 | 0 | Single host |

> **Formula:** `Usable Hosts = 2^(32 − prefix) − 2`
> *(subtract 2 for Network ID and Broadcast Address)*

### VLSM vs Fixed Subnetting

| Feature | Fixed Subnetting | VLSM |
|---------|-----------------|------|
| Subnet size | Same for all | Different per subnet |
| IP utilization | Wasteful | Efficient |
| Flexibility | Low | High |
| Planning | Simple | Requires careful design |
| Used in | Old classful networks | Modern networks & AWS VPCs |

### VLSM in AWS — Real-World VPC Example

When creating a **VPC** in AWS, VLSM is applied to allocate subnets efficiently:

```
VPC: 10.0.0.0/16  (65,536 IPs total)

├── Public  Subnet: 10.0.1.0/24   → 254 usable hosts  (web servers)
├── Private Subnet: 10.0.2.0/23   → 510 usable hosts  (app servers)
└── DB      Subnet: 10.0.4.0/28   →  14 usable hosts  (databases)

→ DB subnet saves 240+ IPs compared to a /24 allocation
```

---

### Key Formulas

```
Usable Hosts     = 2^(32 - prefix) - 2
Number of Subnets = 2^(borrowed bits)

CIDR /24  →  255.255.255.0    →  254 usable hosts
CIDR /25  →  255.255.255.128  →  126 usable hosts
CIDR /26  →  255.255.255.192  →   62 usable hosts
CIDR /27  →  255.255.255.224  →   30 usable hosts
CIDR /16  →  255.255.0.0      →  65,534 usable hosts
CIDR /8   →  255.0.0.0        →  16,777,214 usable hosts
```
